# خادم بستان التعلّم

مشروع Laravel داخل المجلد الفرعي backend، مع دخول للمشرفين ولوحة تأليف تحفظ مسودات المحتوى والاختبارات في MySQL. تشمل اللوحة مكتبة قابلة للبحث والتصفية، والتعديل، وتنزيل JSON، وسلة محذوفات واستعادة، وسجل عمليات وأرقامًا من قاعدة البيانات. نشر المسودات إلى موقع الطلاب ومتابعة تقدّمهم لم يُربطا بعد.

## التشغيل المحلي

المتطلبات: PHP ٨٫٢ أو أحدث وComposer وMySQL، مع امتدادات Laravel وpdo_mysql وGD لفحص الصور، وpdo_sqlite للاختبارات في الذاكرة. اضبط post_max_size في PHP على 16M أو أكثر لاستيعاب المسودات الكبيرة. استُخدم Laravel ١٢ ليتوافق مع PHP ٨٫٢ المتاح على الجهاز.

من داخل backend:

```powershell
composer install
if (!(Test-Path .env)) { Copy-Item .env.example .env }
if (Select-String -Path .env -Pattern '^APP_KEY=\s*$' -Quiet) { php artisan key:generate }
```

شغّل MySQL من Wamp أو من خادم التطوير، واضبط DB_HOST وDB_PORT وDB_DATABASE وDB_USERNAME وDB_PASSWORD داخل .env فقط. الإعداد الافتراضي يشير إلى قاعدة تطوير مستقلة باسم abboud_math_backend على 127.0.0.1:3306. اسم root وكلمة المرور الفارغة في المثال يلائمان بعض تثبيتات Wamp المحلية؛ استخدم بيانات اتصالك الفعلية.

أنشئ قاعدة التطوير باستخدام عميل MySQL أو phpMyAdmin؛ لا تستعمل قاعدة موجودة لطلاب أو مشروع آخر. مثال من عميل MySQL بعد الاتصال:

```sql
CREATE DATABASE IF NOT EXISTS abboud_math_backend
    CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

ثم من داخل backend:

```powershell
php artisan migrate
php artisan serve --host=127.0.0.1 --port=8000
```

نفّذ توليد المفتاح فقط في التثبيت الأول عندما تكون APP_KEY فارغة؛ تغيير مفتاح موجود قد يبطل البيانات المشفّرة والجلسات. لا تستبدل .env أو قاعدة موجودة. في هذه النسخة المحلية أُنشئت البيئة والمفتاح وقاعدة MySQL ورُحّلت جداولها؛ يكفي تشغيل MySQL وأمر serve للتشغيل اللاحق. في أي نسخة جديدة نفّذ خطوات التثبيت أعلاه. افتح http://127.0.0.1:8000 . يمكن استخدام composer dev لتشغيل خادم PHP نفسه؛ لا تحتاج صفحة التهيئة إلى npm أو Vite أو CDN. composer install يحتاج إنترنت مرة لتنزيل الحزم، وبعده يعمل الخادم محليًا دون اتصال بالإنترنت مع استمرار تشغيل MySQL المحلي.

MySQL هو اتصال التطبيق للتطوير، بينما تستخدم الاختبارات SQLite في الذاكرة. لا توجد بيانات طلاب منسوخة ولا حساب افتراضي مزروع. لا تستعمل migrate:fresh على قاعدة فيها بيانات تريد الاحتفاظ بها.

## حساب المشرف والدخول

بعد تشغيل الترحيلات، أنشئ حسابك باختيار صريح من طرفية تفاعلية داخل backend:

```powershell
php artisan admin:create
```

يطلب الأمر الاسم والبريد وكلمة المرور وتأكيدها. إدخال كلمة المرور مخفي، ولا يوجد خيار لتمريرها ضمن سطر الأوامر أو مفتاح افتراضي لها. اختر عبارة من ١٢ محرفًا على الأقل وبحد أقصى ٧٢ بايت، لأن bcrypt يحسب الحروف العربية متعددة البايتات. البريد الموجود يُرفض دون تغيير الحساب أو منحه صلاحية.

افتح http://127.0.0.1:8000/login ثم ادخل إلى /admin. لا يوجد تسجيل عام للحسابات. الترحيل يضيف is_admin بقيمة false للحسابات الموجودة؛ لا يصبح أي مستخدم مشرفًا تلقائيًا، ولا يمكن تعيين الصلاحية عبر حقول المستخدم القابلة للملء العام.

الدخول يقتصر على حسابات المشرفين، وتُفحص الصلاحية عند كل زيارة للصفحة الخاصة. تُجدّد هوية الجلسة عند الدخول، وتُلغى الجلسة ورمز CSRF عند الخروج عبر POST. يُحد الدخول بعد خمس محاولات فاشلة للبريد وعنوان IP معًا، أو ثلاثين محاولة فاشلة لعنوان IP عبر عناوين بريد مختلفة، لمدة دقيقة. استجابات الدخول والإدارة والخروج تحمل no-store ولا تُسجّل عامل خدمة.

في .env الموجود من التهيئة السابقة، أضف SESSION_COOKIE=bustan_backend_session لفصل كوكي الجلسة عن مشاريع Laravel الأخرى على الجهاز. في الإنتاج استخدم HTTPS وSESSION_SECURE_COOKIE=true إلى جانب APP_DEBUG=false. تغيير اسم الكوكي يطلب تسجيل الدخول مجددًا.

## استخدام لوحة التحكم

- من «منشئ المحتوى» أضف وحدة أو درسًا أو مغامرة أو مختبرًا، وأدخل التفاصيل والأهداف والمراجع والصور والصيغ الرياضية. اكتب اسم المسودة ثم اضغط «حفظ في الخادم». يمكن حفظ مسودة ناقصة وإكمالها لاحقًا.
- من «مصمم الاختبارات» أضف أسئلة اختيار من متعدد أو صواب وخطأ أو إجابة قصيرة. المعاينة تفصل نسخة الطالب عن مفتاح المعلّم؛ بيانات الإجابات تبقى داخل مساحة المشرفين.
- «مكتبة المحتوى» تعرض ١٢ مسودة في الصفحة، وتدعم البحث بالعنوان والتصفية حسب النوع، والفتح والتعديل وتنزيل نسخة JSON. النقل إلى السلة قابل للاستعادة ولا يحذف المحتوى نهائيًا.
- بعد الحفظ يصبح للمسودة رابط مثل /admin#quiz-builder/12؛ تحديث الصفحة يعيد فتح النسخة المحفوظة. التعديل يحتاج ضغط الحفظ، والمغادرة تنبّه إلى التغييرات غير المحفوظة. إذا تعذّر الاتصال تبقى التغييرات في المحرر ولا تظهر رسالة نجاح.
- كل مشرف مصرّح له يدير المكتبة المشتركة. رقم revision يمنع الكتابة فوق تعديل أحدث من تبويب أو مشرف آخر؛ عند التعارض يُرفض الحفظ برمز 409 وتبقى تغييرات المحرر للتصدير أو المراجعة.
- النظرة العامة تحسب المسودات وعناصرها وأسئلتها من قاعدة البيانات وتعرض آخر ٨ عمليات. قسم المشرفين يعرض الحسابات الفعلية (حتى ٢٠ حسابًا مع الإجمالي)، وإضافة الحسابات من admin:create.
- «مواد الموقع» تقرأ الفهرس الحالي من catalog.js. اضبط STUDENT_SITE_URL داخل .env على رابط جذر موقع الطلاب لتفعيل روابط المواد؛ تركه فارغًا يعرض أن الرابط غير مضبوط.
- قسم الطلاب يوضح أن المتابعة لم تُربط. لا توجد أسماء طلاب أو نسب نجاح مولّدة، ولا تقرأ هذه اللوحة تخزين تقدّم الطلاب في المتصفح.

التصميم وملفات العرض الأساسية تُقرأ من admin وassets وcatalog.js في المستودع نفسه عبر قائمة أصول ثابتة محمية بالصلاحيات، بينما نسختا المحررين المتصلتين بالخادم داخل resources/js/admin. احتفظ ببنية المستودع عند النشر؛ لا تنقل backend وحده. لا تُحمَّل demo-data.js أو profiles.js أو عامل الخدمة العام، ولا تُنسخ واجهة المعاينة إلى public.

## واجهة الحفظ الخاصة

كل المسارات التالية تحت /admin/api، وتتطلب جلسة مشرف. الكتابة تتطلب CSRF، واستجابات الإدارة والأصول الخاصة تحمل no-store. لا توجد واجهة عامة للمسودات أو مفتاح الإجابة.

| الطلب | الوظيفة |
| --- | --- |
| GET /session | رمز CSRF الحالي للجلسة |
| GET /summary | الإجماليات، آخر العمليات، حسابات المشرفين |
| GET /documents | قائمة دون حمولة الأسئلة؛ kind وsearch وtrash وpage اختيارية |
| POST /documents | إنشاء: kind يساوي content أو quiz، مع title وdocument |
| GET /documents/{id} | قراءة مسودة موجودة خارج السلة |
| PUT /documents/{id} | تعديل title وdocument مع revision الحالي |
| DELETE /documents/{id} | نقل إلى السلة مع revision |
| POST /documents/{id}/restore | استعادة من السلة مع revision |

تُحفظ وثائق bustan-content-draft-v1 وbustan-quiz-draft-v1 بعد فحص خادمي للحقول والأنواع والحدود والمعرّفات والروابط والصيغ الرياضية. الحد الأقصى للوثيقة ١٢ ميغابايت، و١٠٠ عنصر محتوى أو سؤال. الصفوف المتاحة للتأليف ٦ و٨ والمواد الرياضيات والعربية والإنجليزية والعلوم. روابط العناصر يجب أن تبقى في الصف والمادة والفصل نفسه. الصور مضمّنة PNG/JPEG/WebP حتى ٥٠٠ كيلوبايت و١٦٠٠ بكسل للبعد الواحد؛ يفحص الخادم النوع والأبعاد ويفك الصورة باستخدام GD. لا تُقبل صور بروابط خارجية أو SVG. عمليات الحفظ والسجل ضمن معاملة واحدة، وتبقى المسودات خاصة حتى اكتمال مسار المراجعة والنشر.

## الاختبار

```powershell
php artisan test
composer validate --strict
composer audit
```

ومن جذر المستودع لفحص نسختي المحررين المستخدمتين داخل Laravel:

```powershell
node backend/tests/authoring-builders.cjs
```

الاختبارات تستخدم SQLite في الذاكرة؛ لا تفتح قاعدة التطوير. رابط /up يفحص إقلاع Laravel، ولا يثبت اتصال قاعدة البيانات أو جاهزية المزامنة.

## الاستضافة والربط

- GitHub Pages يشغّل الموقع الثابت فقط ولا يشغّل PHP. ارفع Laravel لاحقًا إلى استضافة PHP، واجعل جذر الويب backend/public فقط. لا تجعل جذر المستودع أو backend جذر الويب للخادم.
- .env والمفاتيح وقواعد SQLite وvendor وملفات السجلات مستثناة من Git. composer.lock محفوظ لإعادة تثبيت الحزم نفسها. في الإنتاج اضبط APP_ENV=production وAPP_DEBUG=false وAPP_URL الصحيح وHTTPS وإعدادات قاعدة البيانات.
- لا تُضمّن أسرارًا في واجهة الإدارة أو JSON العام. يلزم تسجيل الدخول والصلاحيات والتحقق من البيانات والصور في الخادم قبل إتاحة أي كتابة.
- قدّم اللوحة الخاصة من أصل مستقل عن المعاينة الثابتة إذا سبق تسجيل عامل خدمة عليها، واتبع admin/LARAVEL-HANDOFF.md عند مشاركة الأصل. هذه اللوحة لا تسجّل عامل خدمة؛ لا تمس كاش مواد الطلاب أو مفاتيح تقدمهم.
- يُصمَّم نقل التقدّم الحالي وحل التعارضات منفصلًا؛ لم تُحمّل profiles.js أو تُغيَّر مفاتيحها هنا. تبقى قرارات الكتاب واستعادة النسخة الاحتياطية السابقة كما هي.

المنفّذ: دخول المشرفين، التأليف والحفظ والتعديل والصور والمعاينات والمكتبة والسلة وواجهات API الخاصة. المتبقي: نشر المحتوى إلى مواد الطلاب، وإدارة حساباتهم ونتائجهم ومزامنة تقدّمهم؛ لا تُغيَّر ملفات المواد المنشورة أو قرارات D01/D02 من هذه اللوحة.
