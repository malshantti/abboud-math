# تسليم واجهة لوحة التحكم إلى Laravel

هذه واجهة تجريبية ببيانات مصطنعة، وليست لوحة متصلة بحسابات عبّود أو ميرا. لا تتضمن مصادقة، أو حفظًا محليًا لتقدم الطلاب، أو واجهة API، أو مزامنة بين الأجهزة. فتح مادة من الفهرس ينتقل إلى موقع المادة الموجود؛ لا يحمّل بيانات التجربة إلى ملف الطالب.

للمعاينة افتح `admin/` عبر خادم ملفات محلي أو بعد النشر. الملفات مستقلة: `index.html` للهيكل، و`admin.css` للتصميم، و`admin.js` للتفاعلات، و`demo-data.js` لبيانات العرض. يمكن تبديل الأقسام بالروابط، وتصفية الطلاب والمواد، وفتح تفاصيل الطالب، وتنزيل CSV موسوم بوضوح بأنه تجريبي. لا تتضمن الواجهة أزرار حفظ أو نشر وهمية.

قائمة الطلاب جدول ببحث وتصفية وترتيب وصفحات، مع ١٠ أو ٢٥ أو ٥٠ صفًا في الصفحة. تقسيم الصفحات في المعاينة محلي على بيانات العرض. عند ربط أعداد كبيرة، تُنفّذ التصفية والترتيب وتقسيم الصفحات في Laravel، وتعيد الاستجابة الصفحة المطلوبة وإجمالي النتائج فقط؛ لا تُحمَّل ملفات جميع الطلاب إلى المتصفح مرة واحدة. لا يمثل هذا التصميم واجهة API منفذة.

## بيانات العرض

منشئ الاختبارات قسم مستقل عن بيانات الطلاب التجريبية. توثيقه في `QUIZ-BUILDER.md`، وتوثيق الصيغ الرياضية في `MATH-EDITOR.md`. يحتفظ بالتأليف في الذاكرة ويتيح نقل ملف مسودة بالصور ومفتاح المعلّم؛ لا ينشر أو يُسند اختبارات إلى طالب قبل ربط الخادم.

يعرّف `demo-data.js` الكائن `window.ADMIN_DEMO`. أسماء المواد ومساراتها مأخوذة من المواد المتاحة في `../catalog.js`. الأوصاف مختصرة، ولا تعد بتسجيل صوتي لكل جملة أو بمحاكاة لكل فكرة.

| الحقل | معنى البيانات التجريبية |
| --- | --- |
| `students` | مثالان للعرض باسم عبّود وميرا؛ لا يمثلان سجليهما الحقيقيين |
| `id` | معرّف تجريبي يبدأ بـ `demo-`، وليس معرّف حساب Laravel |
| `name`، `grade`، `avatar` | بيانات تقديم المثال؛ الصورة ملف محلي موجود |
| `subjects` | أمثلة للمواد الأربع لكل طالب |
| `completed`، `total` | بسط ومقام افتراضيان لعرض شريط التقدم؛ المقام ليس عدد دروس الكتاب الفعلي |
| `assessment` | نتيجة افتراضية من مئة للعرض فقط |
| `focus` | اقتراح توضيحي مصطنع؛ لا ينتج عن تشخيص الطالب الحقيقي |
| `courses` | الصفان السادس والثامن، وفي كل منهما المواد الأربع المتاحة |
| `path` | مسار نسبي إلى موقع المادة من مجلد `admin/`؛ يُراجع عند نقل الواجهة إلى Laravel |
| `status` | توافر موقع المادة في الفهرس، وليس اعتماد دقة كل محتواها |

تُعرض الأرقام للمستخدم بالأرقام العربية الهندية، مع إبقاء القيم العددية في البيانات أعدادًا قابلة للحساب. يجب إبقاء وسم «بيانات تجريبية» ظاهرًا ما دامت هذه البيانات مستخدمة، وألا تُخلط الأرقام المصطنعة ببيانات الطلاب الفعلية.

## تعريف المؤشرات عند الربط

لا توجد حاليًا نسبة إتقان موحّدة بين المواد، ولا يكفي تغيير مصدر البيانات للاحتفاظ بالتسمية نفسها:

- الرياضيات تحفظ حالات المهارات، ومحاولات التدريب وإجاباته الصحيحة، ونتائج الاختبارات. الإتقان يعتمد شروط الاختبار وتغطية الأهداف؛ دقة التدريب ليست دقة كل الإجابات. المرجع: `../g8/math/app.js`، الدوال `summary` و`quizRun` و`V.quiz`.
- الإنجليزية تحفظ نتيجة اختبار الوحدة، ودقة مهارات مثل الاستماع، ونتيجة تحديد المستوى. تُعد الوحدة متقنة في التطبيق عند أفضل نتيجة اختبار تبلغ ٨٠٪ فأكثر. المرجع: `../g6/english/app.js`، الدالتان `unitStatus` و`enSummary`.
- العربية والعلوم تعدّ أقسام المنهاج ذات القيمة `done` التي تبلغ ٧٠٪ فأكثر، وتفصل الأنشطة الإضافية عنها. المرجع: `../g6/arabic/core.js` و`../g6/science/core.js`، الدالة `mastery`.
- يمكن في العربية تسجيل اكتمال قسم قراءة بزر يكتب `done=100` دون اختبار؛ لذلك لا تصح تسمية هذه القيمة دائمًا «نتيجة اختبار». المرجع: `../g6/arabic/ar.js`، المعالج الخاص بزر `mark`.
- مدة التعلم غير متاحة بالتعريف نفسه لكل المواد: الرياضيات تعد الوقت في مهارة والصفحة ظاهرة، والإنجليزية تعد دقائق ظهور الصفحة، ولا تحفظ حالة العربية والعلوم مدة مماثلة. لا تُعرض مدة إجمالية شاملة من هذه الحقول المتفاوتة.
- سجل الإنجليزية محدود بآخر ٣٠٠ نشاط، وسجل العربية والعلوم بآخر ٢٠٠؛ لا يُقدّم السجل على أنه تاريخ شامل لكل نشاط سابق.

عند غياب بيانات حقيقية يُعرض «لا توجد بيانات»؛ لا تُستبدل النتيجة المفقودة بصفر. يجب تحديد معنى `completed` ومقامه ونوع `assessment` لكل مادة قبل ربطها بملخص خادمي، مع إظهار وحدة القياس للمستخدم.

## نقاط الربط المقترحة

يمكن تحويل الصفحات إلى قوالب Blade يزوّدها Laravel بالبيانات، أو الاحتفاظ بواجهة JavaScript واستبدال مصدر التجربة بطبقة تقرأ استجابات JSON. لا تفرض هذه الواجهة أسماء endpoints أو بنية قاعدة بيانات. يحدد تطبيق Laravel عقد البيانات النهائي ويعيد للواجهة حقول العرض اللازمة فقط.

يكون الدخول والتحقق من الأدوار والصلاحيات على الخادم. تُحمى عمليات التعديل من CSRF وفق طريقة مصادقة Laravel المستخدمة، مع تحقق خادمي من المدخلات وصلاحية الوصول إلى كل طالب. إخفاء زر في الواجهة ليس تحققًا من الصلاحية، ورقم الطالب السري المحلي ليس مصادقة لخادم.

لا تُعرض أزرار الحذف أو تعديل المحتوى أو استيراد التقدم بوصفها عمليات مكتملة قبل وجود ربط خادمي فعلي. يجب توفير حالات التحميل والخطأ والفراغ وانتهاء الجلسة، وعدم ادعاء نجاح الحفظ أو المزامنة اعتمادًا على تغيير واجهة العرض.

## التقدم الحالي والخصوصية

يحفظ الموقع تقدم الطلاب محليًا. تحدد `../profiles.js` مفاتيح المواد الثماني ضمن `PER`، وتتيح `dataOf(id, key)` قراءة تقدم المادة، وتدير نسخ الطلاب وتبديلهم. لا تغيّر هذه الواجهة تلك المفاتيح أو تقدم الطلاب.

لا يُحمّل `profiles.js` للحصول على بيانات التجربة؛ تهيئته تنفذ استعادة وترحيلًا للتخزين المحلي، وليست مجرد قراءة. لا تُرسل النسخة الاحتياطية الخام إلى واجهة لوحة التحكم؛ فهي تتضمن بيانات حساب محلية، ومنها الرقم السري المجزّأ والملح. يحتاج نقل التقدم إلى Laravel إلى تصميم مستقل يحافظ على البيانات الحالية، ويحدد معالجة التعارضات بين الأجهزة. هذا النقل غير منفذ هنا.

يقتصر التخزين دون إنترنت للوحة التجريبية على ملفاتها العامة وصورها وخطوطها. عند الربط، لا تُخزّن استجابات API الخاصة أو بيانات الطلاب أو صفحات الإدارة المصادَق عليها في service worker. تُضبط سياسات الاستجابة والتخزين على الخادم كذلك، ولا يُعتمد على إعداد الواجهة وحده. لا تعني إتاحة ملفات العرض دون إنترنت أن الدخول أو عمليات الخادم تعمل دون شبكة.

العامل `admin/sw.js` مخصص للمعاينة العامة فقط، ويخزّن حاليًا `admin/index.html` وبيانات التجربة ضمن قائمة صريحة. **قبل تحويل HTML إلى صفحة Blade تتضمن معلومات خاصة:** أزل تسجيل هذا العامل من نسخة الإنتاج، وألغِ تسجيل العامل السابق ونظّف كاش المعاينة في عملية الانتقال، أو استبدله بسياسة تستثني تمامًا صفحات الإدارة والبيانات المصادَق عليها. لا يكفي حظر مسارات API وحدها إذا أصبحت صفحة HTML نفسها تحتوي بيانات طالب. لا تُحذف كاشات مواد الطلاب أو مفاتيح تقدمهم أثناء ذلك.

## قبل تشغيل البيانات الحقيقية

١. استبدال بيانات التجربة بعقد بيانات موثّق، وإزالة وسم التجربة فقط عند اكتمال الربط.

٢. اعتماد تعريفات التقدم والنتائج لكل مادة، ومعالجة القيم المفقودة دون تحويلها إلى أصفار.

٣. اختبار صلاحيات الوصول عبر الخادم، وحالات الخطأ وانتهاء الجلسة، وسلوك التخزين المؤقت الخاص بالبيانات الحساسة.

٤. اختبار الصفحات على الهاتف والحاسوب، مع اتصال ضعيف أو منقطع، والتأكد من عدم إظهار نجاح وهمي للحفظ أو المزامنة.

## تأليف المحتوى

أُضيف منشئ الوحدات والدروس والمغامرات والمختبرات كمسودات ذاكرة مع معاينات تفاعلية. عقد الحزمة والتحقق وروابط المحتوى موثقة في [CONTENT-BUILDER.md](CONTENT-BUILDER.md). الربط بالحفظ والمراجعة والنشر والصلاحيات يقع على Laravel؛ التصدير ليس نشرًا للطلاب.
