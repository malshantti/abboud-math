# مصمم الاختبارات: واجهة ومسودات محلية

مصمم الاختبارات واجهة تأليف ومراجعة فقط. لا ينشر اختبارًا، ولا ينشئ حسابًا، ولا يحفظ مسودة في `localStorage` أو `IndexedDB`، ولا يرسلها إلى API. تبقى المسودة في ذاكرة الصفحة أثناء التنقل بين أقسام اللوحة، وتُفقد عند إعادة التحميل أو إغلاق الصفحة. يمكن تصدير المسودة الفارغة أو الناقصة واستكمالها لاحقًا؛ لا يلزم إكمال الاختبار لحفظ عمل التأليف. يحتوي الملف على مفتاح الإجابة؛ لا يوزّع على الطلاب.

لا توجد أسئلة جاهزة تدّعي مطابقة المنهاج. يكتب المعلّم النص والخيارات والإجابات، ويتحقق من كتاب المنهاج الفلسطيني وطبعة الكتاب وطريقة الحل. مرجع الكتاب والصفحة حقلا توثيق اختياريان، وليسا تحققًا تلقائيًا من المحتوى.

## الاستخدام

١. أدخل عنوان الاختبار، والصف السادس أو الثامن، والمادة. المدة اختيارية.

٢. أضف سؤال اختيار من متعدد، أو صواب وخطأ، أو إجابة قصيرة. حدّد النص والعلامة ومفتاح الإجابة.

٣. اختر سؤالًا من القائمة لتعديله. يمكن نقله إلى أعلى أو أسفل، أو حذفه. يتيح زر «تراجع عن حذف السؤال» استعادة آخر سؤال محذوف إلى موضعه، بما فيه الصورة ومفتاح الإجابة. لا ينقل التراجع سؤالًا من مسودة سابقة بعد استيراد ملف مختلف.

في مادة الرياضيات يتاح مصمم للكسور والجذور والأسس والنص الرياضي. اختر موضع التعبير: نص السؤال أو أحد الخيارات الأربعة، ثم أضف أجزاءه ورتّبها. يبقى التعبير محفوظًا إذا غُيّرت المادة. يمكن أن يحتوي الخيار على تعبير فقط دون نص، لكن يلزم اكتمال التعبير قبل المعاينة. لا يغير المصمم رموز س وص أو يحسب جوابًا تلقائيًا. شرح بنية التعبيرات وحدودها في `MATH-EDITOR.md`.

٤. افتح المعاينة بعد استكمال الحقول. تبدأ بنسخة الطالب دون الإجابات. إظهار مفتاح الإجابة للمعلّم خيار صريح، ويعود مغلقًا عند فتح المعاينة من جديد. إدخال إجابة في المعاينة لا يُحفظ ولا يُصحّح.

٥. صدّر المسودة للاحتفاظ بها ولو كانت ناقصة، أو استورد ملفًا صالح البنية لاستكماله. عند وجود مسودة حالية يطلب الاستيراد تأكيد استبدالها. لا تُعدل المسودة الحالية إذا فشل التحقق من الملف. تختلف صلاحية الحفظ عن جاهزية المعاينة: المعاينة تتطلب عنوانًا وأسئلة مكتملة ومفتاح إجابة صحيحًا.

تقبل الحقول الرقمية الأرقام العربية الهندية والفارسية والغربية، ويعرضها المصمم بالأرقام العربية الهندية. القيم العددية في JSON تبقى أعدادًا معيارية قابلة للحساب.

## صور الأسئلة

لكل سؤال صورة اختيارية من الجهاز بصيغة PNG أو JPEG أو WebP. يقبل الرفع ملفًا حتى ٨ ميبيبايت، ثم يفكّ المتصفح الصورة ويعيد تجهيزها مع حفظ نسبة الأبعاد: ضلع أقصى ١٦٠٠ بكسل وحجم أقصى ٥٠٠ كيبيبايت. يمكن استبدال الصورة أو حذفها، وتُرفض SVG والروابط الخارجية والملفات ذات التوقيع المخالف. لا يحتاج العرض إلى إنترنت؛ تحفظ الصورة مضمّنة في JSON.

الحقل الاختياري `questions[].image` يحتوي `dataUrl` و`mime` و`width` و`height` و`alt`. الوصف البديل نص حتى ٣٠٠ حرف؛ يمكن تركه فارغًا أثناء حفظ المسودة، ويجب استكماله قبل معاينة الاختبار. تُراجع أبعاد الملف الفعلية عند التحقق، وتُفك صور الملف المستورد في المتصفح قبل استبدال المسودة الحالية. لا يستبدل اختيار ملف غير صالح الصورة السابقة.

الحد الإجمالي للملف المستورد والمصدّر هو ١٢ ميبيبايت، ويشمل الصور والتنسيق المستخدم في التصدير. تقاس البايتات الفعلية؛ لا تعتمد الحدود على عدد الحروف وحده. لا يُسمح لرفع صورة متأخر أن يلحق بسؤال آخر بعد تبديل السؤال أو المسودة.

## عقد ملف المسودة

الإصدار: `bustan-quiz-draft-v1`.

| الحقل | النوع والحدود |
| --- | --- |
| `version` | النص الثابت للإصدار أعلاه |
| `metadata.title` | نص حتى ١٦٠ حرفًا؛ يمكن تركه فارغًا في المسودة، ويلزم للمعاينة |
| `metadata.grade` | العدد ٦ أو ٨ |
| `metadata.subject` | `math` أو `arabic` أو `english` أو `science` |
| `metadata.durationMinutes` | `null` أو عدد صحيح من ١ إلى ٣٠٠ |
| `questions` | من صفر إلى ١٠٠ سؤال في المسودة، وسؤال واحد على الأقل للمعاينة |
| `questions[].id` | معرّف فريد بطول أقصى ٥٠ محرفًا، يبدأ بحرف لاتيني صغير، ثم حروف صغيرة أو أرقام أو شرطات |
| `questions[].type` | `mcq` أو `tf` أو `short` |
| `questions[].prompt` | نص حتى ٣٠٠٠ حرف؛ يمكن تركه فارغًا في المسودة، ويلزم للمعاينة |
| `questions[].points` | عدد صحيح من ١ إلى ١٠٠، أو `null` في المسودة غير المكتملة |
| `questions[].reference.book` | نص اختياري حتى ٢٠٠ حرف، بما في ذلك النص الفارغ |
| `questions[].reference.page` | `null` أو عدد صحيح من ١ إلى ٢٠٠٠ |
| `mcq.options` | أربعة نصوص، كل منها حتى ٥٠٠ حرف؛ يمكن فراغها وتكرارها في المسودة. للمعاينة يجب أن تختلف الخيارات، وأن يحتوي كل خيار على نص أو تعبير رياضي مكتمل |
| `mcq.answer` | فهرس الخيار الصحيح: عدد صحيح من صفر إلى ثلاثة، أو `null` في المسودة |
| `tf.answer` | قيمة منطقية `true` أو `false`، أو `null` في المسودة |
| `short.acceptedAnswers` | حتى عشرة نصوص، كل منها حتى ٥٠٠ حرف؛ يقبل مصفوفة فارغة في المسودة. للمعاينة يجب وجود إجابة واحدة على الأقل، غير فارغة، واختلاف الإجابات |
| `questions[].math` | تعبير اختياري ببنية `{version:1,tokens:[...]}`، وفق عقد محرر الرياضيات |
| `mcq.optionMath` | مصفوفة اختيارية من أربع خانات؛ كل خانة `null` أو تعبير رياضي للخيار المقابل |

تُرفض الخيارات والإجابات المكررة عند المعاينة بعد حذف الفراغات الطرفية وتوحيد أشكال الأرقام وتطبيق NFC، مع الحفاظ على حالة الأحرف والتشكيل: `A` و`a` مختلفان، بينما ٣ و`3` قيمتان متطابقتان للعرض. تتضمن مقارنة الخيار تعبيره الرياضي كذلك. لا يطبّق المصمم تصحيحًا آليًا للإجابة القصيرة أو تطبيعًا لغويًا يغيّر معناها. حجم الملف المستورد والمصدّر الأقصى ١٢ ميبيبايت. يبقى التحقق من الأنواع وحدود الطول والعدد والمعرّفات وشكل التعبيرات صارمًا حتى عند حفظ مسودة ناقصة؛ لا تُقبل قيم غير معرّفة أو أعداد خارج الحدود. يُتحقق من جميع الحقول المعتمدة وتُنسخ إلى بنية جديدة؛ لا تُدمج حقول JSON غير المعروفة في حالة التطبيق.

يُحذف التعبير الاختياري من السؤال عند إزالة جميع أجزائه، وتُعاد خانة تعبير الخيار إلى `null`. تبقى التعبيرات الناقصة غير الفارغة قابلة للحفظ، لكنها تمنع المعاينة حتى اكتمال حقولها. المقام صفر غير مقبول في الحفظ أو المعاينة.

## تكامل الواجهة

تحميل `math-editor.js` قبل `quiz-builder.js`، وكليهما قبل `admin.js`، وتحميل أنماطهما بعد أنماط اللوحة. يعرض `window.QUIZ_BUILDER.mount(container)` القسم داخل عنصر موجود، مع الاحتفاظ بالمسودة في ذاكرة الموديول أثناء التنقل. تعيد `window.QUIZ_BUILDER.validateDraft(value, {allowIncomplete:false})` كائنًا بالشكل `{ok, errors, draft}`؛ تحتوي `draft` نسخة معتمدة من الحقول المسموحة عند النجاح، أو `null` عند الفشل. القيمة الافتراضية `false` للتحقق من جاهزية المعاينة؛ يستخدم الاستيراد والتصدير الدالة نفسها مع `allowIncomplete:true` لحفظ عمل التأليف الجزئي. عند وجود تعبير يستدعي التحقق `MATH_EDITOR.validate` بالوضع نفسه.

المعرّفات الأساسية: `qb-title`، `qb-grade`، `qb-subject`، `qb-duration`، `qb-add-mcq`، `qb-add-tf`، `qb-add-short`، `qb-question-list`، `qb-prompt`، `qb-points`، `qb-reference`، `qb-page`، `qb-answer`، `qb-option-0` إلى `qb-option-3`، `qb-accepted`، `qb-export`، `qb-import`، `qb-file`، `qb-preview`، `qb-preview-dialog`، `qb-teacher-key`، `qb-errors`، `qb-status`.

معرّفا الربط الرياضي: `qb-math-target` لاختيار السؤال أو الخيار، و`qb-math-editor` لحاوية المحرر المستقل. لكل تغيير موضع أو سؤال تُنهى نسخة المحرر السابقة، ولا يعاد إنشاء حقول السؤال عند كتابة جزء رياضي.

## عند ربط Laravel

يفصل الخادم بين المسودة والاختبار المنشور وبين نسخة الطالب ومفتاح المعلّم. لا يُرسل مفتاح الإجابة إلى الطالب ضمن ملف أو استجابة مخفية في الواجهة. يتحقق Laravel من المصادقة والأدوار والصلاحيات والمدخلات وحدود الملفات وCSRF وفق نمط الربط، ويعيد حساب العلامات على الخادم. تحقق المتصفح يحسن تجربة التأليف ولا يغني عن تحقق الخادم.

يتطلب النشر لاحقًا حالة خادمية موثّقة وتحققًا من المرجع وموافقة المعلّم، ولا تكفي إضافة زر أو تغيير شارة الحالة. تحدَّد أسماء endpoints وسياسة إصدار الاختبارات وحفظ محاولات الطلاب عند تصميم الجزء الخلفي، ولا يفرض هذا الملف عقد API جاهزًا. لا تُخزّن الاختبارات الخاصة أو مفاتيح الإجابة أو استجابات الإدارة المصادَق عليها في service worker.

عند الربط يرفع الخادم الصور إلى مخزن مناسب ويعيد التحقق من نوعها وحجمها وأبعادها؛ الملف المضمّن هنا وسيلة نقل محلية للمسودة، وليس تنفيذًا لرفع خادمي. لا تُرسل مسودة المعلّم التي تتضمن مفتاح الإجابة إلى واجهة الطالب.
